# ПРОТОКОЛ ОТЧЁТНОСТИ ДЛЯ PRODUCT COMMANDER

С этого момента каждый раз, когда выполняется задача по исправлению ошибок, безопасности, рефакторингу или реализации новой фазы проекта, работа ОБЯЗАТЕЛЬНО завершается отчётом для независимого аудита ChatGPT.

## 1. ОТЧЁТ О ВЫПОЛНЕННОЙ РАБОТЕ
Указывать:
* Какие задачи выполнены, какие нет и почему.
* Какие файлы изменены и для чего.
* Какие решения приняты и какие ограничения остались.
* Какие потенциальные побочные эффекты обнаружены.
* Какие пункты требуют дополнительной проверки.
* Запрещено объявлять задачу полностью выполненной только на основании того, что код написан или тесты прошли.

## 2. ОБЯЗАТЕЛЬНЫЙ UNIFIED GIT DIFF
К каждому отчёту прикладывать полный Unified Git Diff всех изменений, относящихся к текущей задаче.
Требования:
* Показывать реальные изменения кода относительно исходного состояния задачи.
* Включать все изменённые, добавленные и удалённые файлы, относящиеся к задаче.
* Для новых файлов показывать полное содержимое.
* Для удалённых файлов показывать удаляемое содержимое.
* Запрещено заменять код пересказом, многоточиями или фразами «остальной код без изменений».
* Не ограничивать diff только основными файлами.
* Запрещено включать секреты, токены, пароли, .env, реальные ключи шифрования, пользовательские данные и содержимое рабочих баз данных.
* Если diff слишком большой для одного сообщения, разбивать его на нумерованные части и указывать количество частей. Не пропускать файлы.
* Перед созданием отчёта проверять, что diff соответствует именно выполненной задаче и не содержит посторонних изменений.

## 3. ТЕСТЫ И ДОКАЗАТЕЛЬСТВА
Указывать:
* Точные команды запуска тестов.
* Полный результат прогона: количество тестов, успешные тесты, ошибки и пропуски.
* Какие новые тесты добавлены.
* Какие негативные, граничные и конкурентные сценарии проверены.
* Какие важные сценарии остались непроверенными.
* Результат `git diff --check`.
* Результат `git status --short`.
* Текущий commit hash и исходный commit, относительно которого подготовлен diff.
* Запрещено утверждать, что проверка пройдена, если соответствующий тест не запускался.

## 4. ОСОБЫЕ ТРЕБОВАНИЯ К SECURITY AUDIT
Если задача связана с безопасностью:
* Для каждого замечания перечислить исходную проблему, конкретное исправление и доказательство корректности.
* Отдельно указать оставшиеся риски и возможные обходные пути.
* Не считать успешный тест доказательством отсутствия уязвимости.
* Не скрывать неудачные тесты и ошибки.
* Не менять тесты исключительно для того, чтобы они прошли, если это ослабляет проверяемые гарантии.
* Не заявлять о закрытии Security Gate без проверки всех обязательных критериев.

## 5. ФОРМАТ ИТОГОВОГО ОТЧЁТА
Каждый отчёт оформлять строго в следующем порядке:
1. Краткое резюме.
2. Выполненные и невыполненные задачи.
3. Изменённые файлы.
4. Полный Unified Git Diff.
5. Тесты и результаты.
6. Git status и commit hash.
7. Оставшиеся риски и ограничения.
8. Вопросы, требующие решения Product Commander.

## 6. ГРАНИЦЫ РАБОТЫ
* Не переходить к следующей фазе без явного разрешения владельца проекта.
* Не включать реальные платежи, production-секреты или выдачу настоящих цифровых товаров в тесты.
* Если не удаётся предоставить полный diff или проверить конкретное требование, прямо указать это и объяснить причину.
* Цель — обеспечить независимую проверку ChatGPT на основании реальных изменений, результатов тестов и воспроизводимых доказательств, а не только собственного отчёта.
